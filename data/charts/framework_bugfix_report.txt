## BUG-1: daily_loss_pct 盈利日误熔断 [FIXED]
- 文件: core/state.py:82-91
- 旧: `abs(self.daily.net_pnl) / self.balance * 100` (盈盈利日也返回正数)
- 新: `max(0.0, -self.daily.net_pnl) / self.balance * 100` (只算亏损)
- 影响: pre_trade.py:47 在大盈盈利日不再误触发熔断
- 测试: test_bug1_no_mis_trip_on_profit (盈 100 / 余额 1000 = 10% 旧版触发, 新版不触发) ✓
- 测试: test_bug1_loss_day_unchanged (亏 50 / 1000 = 5% 正常返回) ✓

## BUG-2: circuit.reset() 覆写 peak_equity [FIXED]
- 文件: risk/circuit.py:122-135
- 旧: `state.reset_daily()` 调 `DailyStats()` 把 peak_equity 清成 0
- 新: 只清 circuit 自己的 state (ATR 序列 / 滑点累计 / 触发标志), daily stats 由调用方管理
- 影响: 跨日后 DD 统计不再从 0 重启, 真实保留当日峰值
- 测试: test_bug2_peak_equity_preserved (reset 后 peak=1500 保留) ✓
- 测试: test_bug2_circuit_state_cleared (circuit 状态清, daily 不动) ✓
- baseline 验证: multi_factor_m15 DD 39.77% → 39.92% (+0.15pp, 原 BUG 让 DD 偏小)

## BUG-3: IC forward_periods 多周期实现 [FIXED]
- 文件: alpha/factor_engine.py:81-145
- 旧: 硬编码 1-bar forward return, 跟 forward_periods 形参脱钩
- 新: 预计算 fp∈{1,5,10,20} 的 forward return, 输出 ic_1/ic_5/ic_10/ic_20/ic_mean 列
- 影响: IC 报告真实反映多周期信号强度
- 测试: test_bug3_multi_period_ic (5000 bar 真实数据, 100% 因子 ic_1≠ic_5) ✓
- 真实数据示例 (top 3 因子):
  - atr_ratio:    ic_1=+0.024 ic_5=+0.065 ic_10=+0.072 ic_20=+0.077 mean=+0.059
  - keltner_width: ic_1=+0.024 ic_5=+0.061 ic_10=+0.069 ic_20=+0.078 mean=+0.058
  - bb_width:     ic_1=+0.027 ic_5=+0.045 ic_10=+0.035 ic_20=+0.039 mean=+0.037
  - 旧版只看 ic_1, 严重低估 atr_ratio / keltner_width (3× 提升)

## BUG-4: SL/TP slippage 方向 [RETRACTED - 不成立]
- 文件: execution/paper_engine.py
- 复审发现: `_apply_slippage(price, close_dir=-pos.direction)` 在多仓平仓时 close_dir=-1,
  slippage 方向 = `price - slip` (卖出价变低), 实际成交价更低于 SL → 对交易者不利 ✓
- 空仓平仓时 close_dir=+1, slippage 方向 = `price + slip` (买入价变高), 实际成交价更高于 SL → 也正确 ✓
- 原审计误判: 我混淆了 "buy slippage 抬升" 跟 "close 方向" 的关系
- 无修复

## BUG-5: 零净利交易 break-even 单独计 [FIXED]
- 文件: core/state.py (DailyStats + record_trade) + execution/paper_engine.py (_close)
- 旧: net_pnl == 0 走 else 分支计为 losing_trade, 微偏低 WR
- 新: DailyStats 加 `break_even_trades: int = 0` 字段, 三分支 (>/</== 0) 分别计
- 影响: WR 统计更精确, consecutive_losses 不被 0 净利重置 (跟赢不同)
- 测试: test_bug5_break_even_counted (4 笔: 赢 1 / 亏 1 / 零 2 → wins=1 losses=1 break_even=2) ✓
- baseline 验证: 744 笔交易 net_pnl 全部 ≠ 0, 数字不变 (该 bug 在当前 baseline 上未触发)
